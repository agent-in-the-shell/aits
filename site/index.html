Run codingagents fromthe commandline

aits drives Claude Code and Codex for you, queues their work and finds their past conversations. It is built for AI agents to call: one command per action, and with --json, one JSON object on stdout.

Install 
$ go install github.com/agent-in-the-shell/aits/cmd/aits@latest
  • shell submit available
  • task available
  • session search available
  • job available

Needs Go and the claude or codex CLI you already log in to. Check with aits version. aits never talks to a model itself.

01 / synopsis

Four command groups, one grammar.

One grammar for all of them: flags go before or after the prompt, -- ends flags, an unknown flag is exit 2 and never a prompt, and every command that prints output takes --json.

aits shell
available

Run one prompt through Claude Code or Codex. Get the answer and a session id back.

  • aits shell submit --agent claude|codex [--cwd DIR] [--session ID] [--model MODEL] [--timeout DURATION] [--write] [--worktree] [--run-dir BASE] [--report] [--allow-tool TOOL]… [--env NAME]… [--json] (PROMPT | -) {"status":"ok","agent":"claude","session_id":"…","answer":"…","exit_code":0,"duration_ms":12345}
aits task
available

A local work queue. Create tasks now, work them later, chain a follow-up into the same session.

  • aits task create (--agent AGENT | --after ID) [--cwd DIR] [--write] [submit flags] [--json] (PROMPT | -) {"id":"…","status":"queued"}
  • aits task work [--agent AGENT] [--json] the task it ran, or {"status":"empty"} when nothing is claimable
  • aits task wait ID [--timeout DURATION] [--json]
  • aits task list [--json]   aits task show ID [--json]   aits task cancel ID [--json]
aits session
available

Full-text search over the agents' own transcripts. Every result carries a session id you can continue.

  • aits session search [--agent AGENT] [--cwd DIR] [--since DURATION] [--source interactive|scripted] [--limit N] [--json] TERM… {"results":[{"agent":"claude","session_id":"…","cwd":"…","updated_at":"…","snippet":"…"}],"skipped":{"files":0,"lines":0}}
aits job
available

Run the commands cron or launchd starts: a timeout, a lock, a log, a run record and deduplicated alerts.

  • aits job run [--timeout DURATION] [--on-alert PROGRAM] [--env NAME]… [--json] NAME -- COMMAND [ARG…] {"name":"…","status":"ok","exit_code":0,"duration_ms":…,"alert":"none"}
  • aits job list [--json]
  • aits job apply [--dry-run] [--sched] [--json] FILE   aits job sched [--json] FILE

--agent is required unless --after. submit flags are the other flags of shell submit, such as --model, --timeout, --allow-tool and --env. Also: aits version and aits help. Every flag is in the CLI reference.

Notes

  • codex--agent codex runs Codex CLI the same way. Codex only runs inside a git repository. Without --write it runs read-only; with --write it gets -s workspace-write and .git stays read-only, so you commit afterwards.
  • timeout--timeout (default 30m) stops the agent. A timed-out result still carries session_id, so continue with --session and a narrower prompt, or raise --timeout.
  • read-onlyWithout --write the agent can read but not change anything. Claude Code refuses tools that need approval and lists them in denied_tools; a refusal does not change the status, so read answer and denied_tools together.

Notes

  • source--source interactive keeps sessions a person ran. --source scripted keeps ones run by claude -p or codex exec, which includes aits's own runs.
  • scopeSearched: user and assistant message text, and prompts queued while the agent was working. Not searched: tool calls or their output, model thinking, subagent transcripts, compaction summaries.
  • matchEvery term must appear somewhere in the session, ignoring case. Results are newest first, at most --limit (default 20). No match is "results":[] with exit 0.

Notes

  • macOSPrefer a launchd agent in ~/Library/LaunchAgents: it never starts a job again while it is running. Use StartInterval 300 for work and StartCalendarInterval for create.
  • overlapOverlapping cron runs claim different tasks, never the same one, so slow tasks can pile up workers. To keep one, use launchd, or flock -n on Linux.
  • envA scheduled job gets a bare environment. PATH must reach aits and the agent CLI, HOME must be yours, and --env variables are set in the work job, not the create job.
03 / contract

Built to be parsed.

An agent calling aits should never have to guess what happened. The output rules come from the project's principles, and tests against the built binary check them.

Success

For shell submit, the status is ok. An idle task work and a search with no match exit 0 too, so read the result.

1
Failed

A status other than ok, or aits could not finish.

2
Usage error

Or invalid input. Nothing was started or written.

One stream to read

stdout carries only the result. Diagnostics and warnings go to stderr. With --json, errors are JSON on stdout too:

{"error":{"code":"…","message":"…"}}

An explicit status

Empty output never means success. shell submit reports one of:

okagent_failedbad_agent_outputoutput_too_largetimeoutstoppedincomplete

Every status but ok carries a one-line message, and session_id whenever the agent reported one.

Stopped cleanly

Each agent runs in its own process group. On a timeout or a signal, aits sends TERM to the group, then KILL 5s later, waits for it to exit and still prints the result.

aits runs in the foreground: it never forks into the background or writes pid files.

04 / for agents

Teach your agent to use it.

The repo ships an agent skill, skills/aits/SKILL.md, that tells a coding agent when and how to call aits: which command for which job, what each status means, and how to run a review-and-fix loop.

Skill 
$ git clone https://github.com/agent-in-the-shell/aits$ mkdir -p ~/.claude/skills && cp -R aits/skills/aits ~/.claude/skills/
  • Install it where your agent loads skills. For Claude Code, that is ~/.claude/skills.
  • Update it with the binary. Each change to the CLI updates the skill in the same commit, and a test fails when the skill does not name every command, flag and result status.
  • The help wins. When the skill and aits COMMAND --help disagree, the skill tells the agent to follow the help.

05 / scope

A toolbox, not a platform.

aits is the tools an agent calls from a shell. A feature belongs in aits when its caller is an agent or a script, it runs locally and in the foreground, aits adds something of its own, it fits a small binary for every user, and it has a caller today. Principle P15.

What aits is

  • One command per action, with a --json result.
  • Local and in the foreground. It never daemonizes, and no command needs a running aits process.
  • A layer of its own over vendor CLIs: an environment allowlist, sandbox and permissions, timeouts and process groups, recoverable state, one vocabulary for both agents.
  • A client of services that host things, where those exist.

What aits is not

  • A host for services other commands depend on.
  • The agent's loop, a workflow engine or a set of stop conditions. The caller owns the loop.
  • A resident scheduler. cron and launchd run the queue.
  • A TUI, a way to attach to live agents, or a bundle of chat-platform adapters.
